# Architecture

A contributor's map of the Women's World Cup 2023 Schedule Viewer. The README
covers *what the app does*; this covers *how the code is laid out* and how data
flows through it. Day-to-day "what changed when" lives in [`NEWS.md`](./NEWS.md);
the authoritative per-function detail lives in each module's header comment — this
file is the index that points you at the right one.

The app is a client-only React 18 + Vite SPA. There is no backend: all logic
runs in the browser (plus a handful of Node scripts for CI/data regeneration and
one Netlify function for the calendar feed).

## The format, and why it shapes the code

Thirty-two teams, **eight** groups of four, **top two advance** — and no
best-third route. 2023 was the first 32-team women's World Cup, so the knockout
starts at a **Round of 16** and the tournament is 64 matches long.

The absence of a best-third race removes a whole layer the Euro sibling needs:
with no cross-group third-place comparison, every qualification question is
answerable inside a single group. Clinch, elimination and opponent-lock detection
are all per-group here; the Euro viewer's combinations table and cross-group
bounding pass have no counterpart in this repo.

Two format facts to hold onto, because both differ from a sibling in a way that
is silent if you get it wrong:

1. **The entry round re-pairs the groups.** Each group meets the group two letters
   along — 1A-2C, 1B-2D, 1E-2G, 1F-2H — so the halves are A,C,E,G against
   B,D,F,H, and a group's winner and runner-up go to two *different* ties. This is
   NOT the men's 2022 pattern (1A-2B, halves ABCD/EFGH). `ENTRY_ROUND` in
   `slots.js` is `'R16'`, and `check-bracket-consistency.mjs` re-derives all 16
   knockout matchups from the group results to prove the wiring.
2. **Every knockout tie played extra time before penalties**, so `pens` always
   implies `aet` here. Copa América 2024 is the exact opposite (`pens` without
   `aet` is correct there). Never copy a generator line between the two repos.

Like the men's World Cup, this tournament keeps a **third-place play-off** (match
63). It hangs off the bracket rather than sitting in it, and it is the one place
the "Loser Match N" feed form is exercised.

## Data flow at a glance

```
static schedule (src/data)              live feed (src/services)
  matches · teams · venues                 ESPN (live overlay only) ─┐
        │                                                            │
        └──────────────┬─────────────────────────────────────────────┘
                       ▼
        merged matches  (App.jsx state, refreshed on a timer)
                       │
   ┌───────────────────┼──────────────────────────────────────────┐
   ▼                   ▼                   ▼                       ▼
 qualification       clinch /           asItStands            bracketResolve
 (standings,         eliminationCheck   (provisional R16       (fill bracket
  tie-breakers)      (guaranteed        projection)            placeholders as
                      outcomes)                                teams resolve)
                       │
                       ▼
                   components/  (Standings, Bracket, WeekView, …) render it
```

**One runtime feed, not three.** The committed schedule already holds every 2023
result; ESPN only overlays a live clock/score onto matches in progress (and
just-finished ones). OpenFootball publishes the men's World Cups only and
TheSportsDB's free tier has no women's data, so there is no `results.js` "source
of record" module and no `reconcile.js` / "confirmed by N sources" layer in this
repo — with a single feed both would be permanently inert. Do not re-add them.

Everything downstream of the merge is **pure**: given a `matches` array it
recomputes standings, clinches, projections and bracket fills with no side
effects — which is why most logic is unit-testable without the DOM.

## `src/data` — static inputs

| File | Exports | Role |
| --- | --- | --- |
| `matches.js` | `MATCHES`, `STAGE_LABELS`, `STAGE_ORDER` | The frozen 64-match schedule (kickoffs, venues, group/knockout slot labels). Source of truth for structure; regenerated by `fetch:tournament`, asserted against `test/fixtures/official-kickoffs.js`. `STAGE_ORDER` is `Group, R16, QF, SF, 3rd, Final`. |
| `teams.js` | `TEAMS`, `FLAG_BY_TEAM`, `ALL_TEAMS` | 32 teams across 8 groups, flag/name lookups. `FLAG_BY_TEAM[name]` doubles as the "is this a real team?" test in the UI. |
| `venues.js` | `VENUES` | 10 host stadiums (name, city, country, region, IANA `tz`), keyed by stadium — two of them are in Sydney. `country` is the single combined string "Australia & New Zealand" for all ten, so `region` is what separates the hosts. |
| `broadcast.js`, `teamTimezones.js`, `groupColors.js` | — | US TV/streaming (tournament-wide, not per match), per-country kickoff times, group accent colors. |

**No single tournament timezone.** Each match's `ko` carries its *own* venue's
offset (+12 New Zealand, +10 eastern Australia, +09:30 Adelaide, +08 Perth). The
sibling viewers restate every kickoff in one organiser-published zone; that is
impossible here, and code that assumes a single offset will be wrong for three
quarters of the venues. The suite is pinned to `Australia/Sydney` in
`vite.config.js` (0 of 64 matches change calendar day under it).

There is no ranking table and no combinations table. FIFA's last 2023 tie-breaker
is a drawing of lots, not a ranking, so it is stood in for by a stable
alphabetical order (`byLots` in `qualification.js`) rather than by data. (The 2026
men's edition replaced lots with FIFA ranking; there is deliberately no
`fifaRanking.js` here.)

## `src/services` — live data ingestion & merge

- **`espn.js`** — ESPN's public scoreboard, the **live in-match overlay** (clock,
  provisional score, goal/card events) and the `history` window for finals that
  have aged out of the rolling scoreboard. `LIVE_SOURCE`, `fetchLive`, `applyLive`,
  `normEspn`, `scoreboardDates`, `historyDates`. The committed schedule stays the
  source of record: a match that already has a score is left untouched, and the
  static input is never mutated.
- **`teamNames.js`** — canonical-name normalisation (`normalizeTeam`, `isRealTeam`,
  `pairKey`). In the siblings this lives inside the OpenFootball results module;
  with no such module here it stands alone, which is why every other service
  imports its `pairKey` rather than defining one.
- **`espnStats.js`, `espnMatchStats.js`** — Golden Boot enrichment (`fetchBootExtras`,
  `fetchRecentPlayerStats`) and per-match player lines (`fetchMatchLines`) for the
  stats view and player pop-outs.
- **`goalNotify.js`** — opt-in browser goal notifications (`detectGoals`,
  `isLiveish`, `inScope`, `goalNotification`). Only ESPN-driven matches can gain a
  *new* goal; the 164 goals already in the committed schedule must never notify.

`App.jsx` owns the fetch loop: it polls every ~2 min, dropping to ~30 s while any
match is live, and recomputes the derived state below on each refresh.

## `src/utils` — derived logic (pure)

**Standings & qualification**
- `qualification.js` — `computeQualification` (all eight tables), `rankGroup`,
  `headToHead`, `groupComplete`, `rowStatus`, `ADVANCING_PER_GROUP`, `byLots`.
  Implements FIFA's 2023 order: points → **overall goal difference → goals scored**
  → head-to-head points/GD/goals → fair play points → drawing of lots. Two things
  to preserve: overall GD comes **before** head-to-head (the reverse of the Euro
  *and* of the 2026 men's World Cup), and fair play points are **additive** —
  yellow −1, indirect red −3, direct red −4 — not Copa's "a red outranks any
  number of yellows". Group H is the live proof of the first: Morocco beat Colombia
  1–0 yet finished below them on GD (+2 vs −4).
- `tiebreakNotes.js` — `softTiebreaks`, `TIEBREAK_LABEL`: detect placings separated
  only by fair play points or by the drawing of lots (the "⚖️" cases).
- `standings.js` — small presentation helpers for the tables.

**Guaranteed outcomes**
- `clinch.js` — `computeClinch` plus `resolveClinchedSlots` / `resolveRunnerUpSlots`
  (fill group-winner/runner-up bracket slots), `newlyClinched`, `clinchHeadline`,
  `clinchBadge`. Marks teams 🥇/🥈/✅/❌ once mathematically settled. Statuses are
  `won-group | runner-up | top2 | eliminated` — there is no `third`.
- `eliminationCheck.js` — exact per-group scoreline enumeration for
  elimination/advancement: `eliminationStatus`, `survivingTeams`, `isAlive`. Stays
  silent rather than guessing when a group is too open to enumerate; its budget
  covers **two** remaining group matches, so a test scenario leaving three open
  gets "alive" for everyone and passes vacuously.
- `opponentClinch.js` — `lockedOpponent`: has a team's round-of-16 opponent stopped
  being able to change? A two-group question here (a group and the group two
  letters along), and nothing more.

**Projection & bracket**
- `asItStands.js` — `projectKnockout`: the provisional "as it stands" round-of-16
  projection. Returns `perGroup[g] = { first, second }` and nothing else.
- `bracketResolve.js` — `resolveBracket` (full pipeline), `resolveKnockoutSlots`
  (propagate "Winner/Loser Match N" up the rounds), `decideMatch` (winner/loser of
  a finished tie; null while live or drawn without pens). Conservative: a slot
  stays a placeholder until genuinely settled.
- `bracket.js` — `BRACKET` (two-sided layout from the R16 up, plus a `third` key
  for the play-off), `matchesByNum`, `groupSlotMap`, `feederTeams`, `pathToFinal`,
  `knockoutTeams`.
- `slots.js` — the slot-label grammar (`ENTRY_ROUND = 'R16'`, `WINNER_GROUP`,
  `RUNNERUP_GROUP`, `WINNER_MATCH`, `LOSER_MATCH`, `entryMatches`, `slotLabels`).
- `outlookEnum.js` — the (group-stage-only) R16 Outlook: goal-difference margin
  enumeration with weighted per-group dedup. Runs in a web worker. Its `chooseCaps`
  fallback **is** reachable with eight groups (3 open games in a group is 12.8M
  combinations, over `MAX_ITERS`); it is unreachable only from the UI, because
  `OutlookView` bails above `MAX_REMAINING = 14` open games.

**Group-stage tools & misc**
- `scenarios.js` — deterministic what-if picks; `groupStageArchived` / `stageArchived`
  (retire the group-stage-only tabs once every group game is final).
- `tournamentStats.js` — Golden Boot table, tournament totals, `activeTeams`,
  `teamRecord` (the knockout "tale of the tape"), `nameKey` (diacritic-insensitive
  player join).
- `time.js` — `formatTime`, `dayKey`, `matchStatus`, `liveState`,
  `teamLocalKickoffs`, `teamKickoffTooltip`.
- `week.js`, `search.js`, `urlState.js`, `ics.js` — week-calendar bucketing,
  filtering, shareable-URL (de)serialization, `.ics` generation.

## `src/components` & `src/context`

`App.jsx` is the shell: data loop, filters, timezone, spoiler mode, view routing,
and the group-stage-archived gating. `VIEWS` has seven entries — `schedule`,
`week`, `groups`, `scenarios`, `outlook`, `bracket`, `stats` — and any view not in
it degrades to the Bracket, which is what an old `?view=radial` deep link now does
(see below).

Views: `Standings`, `Bracket`, `WeekView`, `StatsView`, plus the group-stage
`ScenariosView` / `OutlookView`. Cards/modals: `MatchCard`, `MatchDetail`,
`DayMatchesModal`, `GroupGamesModal`, `CalendarModal`, `PlayerDetail`, `Filters`,
`NextMatch`, `ChampionBanner`, `LiveBadge`, `FeederPair`, `PathPicker`,
`GoalToasts`, `ScalesIcon`. Cross-cutting state lives in `context/`
(`follow.jsx` for starred teams, `path.jsx` for the traced route to the Final,
`detail.js` for the match-detail modal).

`ScalesIcon` exists because the ⚖️ emoji renders as a missing glyph on some
devices; the tie-break marker is inline SVG, not a character.

The bracket's **potential-matchup** display (a "Winner Match N" slot expanding to
the candidate pair, cascading round by round) lives in `bracket.js`'s
`feederTeams` helper, rendered by `FeederPair` — round-agnostic and per-slot by
construction, which is why both the Round of 16 and the third-place play-off's
"Loser Match N" slots expand with no special case.

**There is no radial bracket view in this edition.** The sibling's
`RadialBracket.jsx` was structurally QF-entry (eight outer leaf slots, two rings),
so it could not show a Round of 16, and it was removed rather than rebuilt. To
bring one back for a future edition, take it from `copa-america-viewer` and
re-derive the rings. Note that the two `--page-bg: radial-gradient(...)`
declarations in `index.css` are the page background, not radial-view CSS.

## `scripts` — data regeneration & CI

Run with `node scripts/<name>.mjs`; the npm aliases are in `package.json`. These
must use **only Node built-ins and in-repo source** (no npm deps) — enforced by
`test/scripts-runtime.test.js`.

- **`fetch-tournament.mjs`** (`npm run fetch:tournament`) — rebuild
  `src/data/{matches,teams,venues}.js` from **two** keyless public sources: FIFA's
  match calendar (the authority: official match numbers 1–64, kickoffs, venues,
  scores) and ESPN's `fifa.wwc` scoreboard (event ids, group labels, goal scorers
  with minutes). **Fails the build unless the two agree on all 64 kickoffs, venues
  and scores.** Also holds `KNOCKOUT` (the fixture list with FIFA's match numbers)
  and `VENUE_META` (the `sponsorName` → official `name` map).
- **`make-official-fixture.mjs`** (`npm run fixture:official`) — rebuild
  `test/fixtures/official-kickoffs.js` from FIFA. Read the honest-limit note at the
  top: because the builder already validates against FIFA, this is not a fully
  independent third opinion the way the siblings' OpenFootball fixture was — its
  value is being a *frozen* record of that agreement, re-checked on every test run.
- **`check-bracket-consistency.mjs`** (`npm run check:bracket`) — re-derives all 16
  knockout matchups from the committed group results and compares them with the
  official draw. This is the guard against "correcting" the pairing toward the
  men's pattern.
- **`coverage-badge.mjs`** — turn the coverage summary into the shields endpoint.
  Note this is what "100% coverage" means in this family: the badge **rounds** the
  statement percentage (≥99.5% prints 100%). There is no coverage threshold in
  `vite.config.js`.

## Outside `src`

- `netlify/functions/calendar.js` — the auto-updating `webcal://` `.ics` feed
  (fetches the live schedule per request; mirrors `utils/ics.js` formatting). It
  is **ESM on purpose**: the package is `"type": "module"`, so a CommonJS function
  502s on the Netlify Git-build path. It is ESPN-backed (`parseScoreboard`), and it
  carries `VENUE_ALIASES` — ESPN files 9 of the 10 stadiums under sponsor names, so
  without it the calendar feed would disagree with the app about where a match was
  played.
- `test/` — Vitest suite (units + jsdom component tests). Fixtures in
  `test/fixtures/` freeze real upstream data (`official-kickoffs.js`,
  `final-group-results.js`, `group-stage-md3.js`, `espn-scoreboard-snapshot.json`,
  `espn-team-names.json`) as regression anchors.
- `test/helpers/tournament.js` — board builders for tests: `unscored`, `playedUpTo`,
  `withGroupScores`, `onlyGroupScores`, `groupTeams`, and `espnScoreboard` (build an
  ESPN-shaped payload from committed matches when a test needs results over the
  wire).

## Conventions

- **Purity downstream of the merge.** Logic takes a `matches` array and returns
  derived data; no module mutates its input. Tests pass synthetic `matches`.
- **Conservative resolution.** Clinch/bracket code only commits an outcome when
  mathematically guaranteed; provisional views (projection, outlook) are where
  "what could happen" lives.
- **Canonical names.** Every feed normalises to the `src/data/teams.js` spelling at
  ingestion, via `services/teamNames.js`. `test/team-resolution.test.js` refuses
  any alias key that never appears in the captured feed — an inherited alias
  (`'United States' → 'USA'`) once rewrote a canonical name to a non-team and
  silently dropped every USA match.
- **This edition is finished.** `src/data/matches.js` ships with every result, so
  tests wanting a pre-tournament board ask for one explicitly via
  `test/helpers/tournament.js`'s `unscored()`. App-level tests of the live layer
  must mock the module to a blank board, or the live overlay always defers to the
  recorded score and the whole subsystem is unreachable — but note that
  `vi.mock('../src/data/matches.js')` also catches the test file's *own* import, so
  a feed built from `MATCHES` inside such a file serves unplayed fixtures and
  asserts nothing. Use `await vi.importActual` for that.
- **Module header comments are the spec.** Before changing a util, read its top
  comment — it states the invariant the rest of the code (and tests) rely on.
